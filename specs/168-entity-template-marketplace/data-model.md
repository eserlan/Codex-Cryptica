# Data Model: Entity Template Marketplace

## Public Entity Template Package

The spec 167 `TemplatePackage`, projected strictly. Defined in `@codex/entity-template-engine`.

| Field                 | Type                 | Rules                                                      |
| --------------------- | -------------------- | ---------------------------------------------------------- |
| `kind`                | `"entity-template"`  | Literal.                                                   |
| `formatVersion`       | integer              | `1` today. Greater than supported is rejected.             |
| `template.name`       | string, 1–80         | Trimmed, single line.                                      |
| `template.entityType` | string, 1+           | Trimmed, lower-cased. Any category, built-in or custom.    |
| `template.markdown`   | string, **1**–50,000 | Non-empty when published (an empty body cannot be shared). |

No other field is allowed. Unknown fields present in a local template are dropped by the projection, never sent.

## Entity Template Listing (`listing.json`)

| Field              | Type                        | Rules                                                                        |
| ------------------ | --------------------------- | ---------------------------------------------------------------------------- |
| `schemaVersion`    | `1`                         |                                                                              |
| `templateKind`     | `"entity"`                  | Discriminator. Stat sheet records omit it (read as `stat-sheet`).            |
| `listingId`        | string (UUID)               | Generated by the worker.                                                     |
| `title`            | string, 1–80                | Copied from the package name.                                                |
| `description`      | string, 1–500               | Plain text.                                                                  |
| `entityType`       | string                      | Lower-cased copy of the package entity type, for filtering.                  |
| `labels`           | string[] (1–8), each 1–30   | Genre/system labels. At least one required. De-duplicated, case-insensitive. |
| `ownerDisplayName` | string, 1–80, optional      | Public attribution. Omitted when not given.                                  |
| `packageVersion`   | integer                     | The package `formatVersion`.                                                 |
| `status`           | `"active" \| "unpublished"` | Operator takedown is a separate suspension marker, not a status.             |
| `listingCreatedAt` | ISO datetime                |                                                                              |
| `listingUpdatedAt` | ISO datetime                | Sort key (newest first).                                                     |

The owner token never appears here. Its hash is stored as R2 custom metadata on `listing.json`, as for stat sheet listings. There is no `importCount`.

## Directory query and page

Query: `kind=entity`, `q`, `entityType`, `labels` (comma list, AND), `cursor`, `limit` (default 24, max 50).

Page: `{ results: EntityTemplateListing[], nextCursor?, facets: { entityTypes: { value: string, count: number }[] } }`. Results are metadata only: no package, no markdown, no token.

Detail: `EntityTemplateListing & { previewMarkdown: string }` where `previewMarkdown` is the package body, returned only for active listings.

## Summary index (`templates/index/entity.json`)

`{ schemaVersion: 1, updatedAt, entries: EntityTemplateListing[] }` containing active entity listings only, without template text or any token. Maintained by the worker on every state change and rebuilt by the operator endpoint. Never contains suspended, unpublished or deleted listings.

## Report

Stored at `moderation/template-reports/{listingId}/{reportId}.json`:

`{ schemaVersion: 1, reportId, listingId, reason, details?, receivedAt }`

- `reason`: one of `inappropriate`, `copied-without-permission`, `spam`, `other` (defaults tuned in UI copy).
- `details`: up to 2,000 characters, optional.
- Reporter de-duplication marker: `moderation/template-report-index/{listingId}/{reporterHash}` (empty body). Daily quota counter: `moderation/template-report-quota/{reporterHash}/{yyyy-mm-dd}` (`{ count }`). `reporterHash` is an HMAC-SHA-256 of the connecting IP, keyed by the `TEMPLATE_REPORT_HASH_KEY` secret. Neither is part of any response.
- Reporter contact is not collected for entity reports.

## Device-local publish link (IndexedDB `settings`)

| Key                                                | Value                                 |
| -------------------------------------------------- | ------------------------------------- |
| `entityTemplatePublishLink:{vaultId}:{templateId}` | `{ listingId, status, publishedAt }`  |
| `templatePublishOwnerToken:{listingId}` (existing) | owner token string                    |
| `entityTemplateReported:{listingId}`               | `true` once reported from this device |

Never written to the vault, the template file, exports or backups.

## Installed template

An ordinary user template created through `EntityTemplateStore.create()`: new local id, `source: "user"`, no reference to the listing. Later listing changes or removal do not affect it.

## State and transitions

Listing lifecycle (worker):

```text
(none) --publish--> active --unpublish (owner)--> unpublished --update/republish (owner)--> active
active | unpublished --owner delete--> deleted (listing, package and index entry removed)
active | unpublished --operator takedown--> suspended (final: owner PUT/unpublish/delete rejected, reads 404, record kept)
```

Publish flow (client): `idle → previewing → acknowledging → sending → published(token shown) | error`. Errors return to `previewing` with the form intact; nothing is linked locally until the worker confirms.

Install flow (client): `idle → loading → validating → needs-name | saving → done`, any state may end in `error` or `cancelled`. Only `saving` mutates the vault, in one `create()` call.

Report flow (client): `idle → sending → reported | already-reported | rate-limited | error`.

## Relationships

`Listing` 1:1 `Package` by `listingId`. `Listing` 1:N `Report`. A local user template has 0..1 device-local link to a `Listing`; a `Listing` can be linked from at most one local template per vault on a device (relinking replaces the previous link).

## Invariants

- Public responses never contain the owner token or its hash, reporter hashes, or any vault or template-local id.
- The summary index always equals the set of active, non-suspended entity listings (worker tests assert this after every transition).
- The public package contains exactly the four package fields (FR-007).
- Install never reads or writes entities and never changes a default (FR-010, SC-005).
- An operator-suspended listing cannot be restored with the owner token (FR-020).
- Stat sheet listing records and their behaviour are unchanged (SC-010).
