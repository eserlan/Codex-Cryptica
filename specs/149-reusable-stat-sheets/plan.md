# Implementation Plan: Lightweight Reusable Stat Sheets

**Branch**: `149-reusable-stat-sheets` | **Date**: 2026-07-31 | **Spec**: [specs/149-reusable-stat-sheets/spec.md](file:///home/espen/proj/Codex-Cryptica-v2/specs/149-reusable-stat-sheets/spec.md)
**Input**: Feature specification from `/specs/149-reusable-stat-sheets/spec.md`

## Summary

Implement a lightweight, system-agnostic **Stat Sheet** feature attached to entities (Characters, NPCs, Ships, Settlements). Stat Sheet definitions reside in entity YAML frontmatter (`statSheet`), supporting manual field controls (`counter`, `number`, `text`, `longtext`, `heading`, `dice`). Includes a template manager (`StatSheetTemplateStore`) to save and apply layout definitions across entities.

---

## Technical Context

**Language/Version**: TypeScript 6.0.3, Bun 1.3.14 + Svelte 5 (Runes), SvelteKit 2  
**Primary Dependencies**: `@codex/vault-engine`, Svelte 5 runes (`$state`, `$derived`, `$effect`), `diceRollerService`, `vttSessionService`  
**Storage**: Entity frontmatter (`statSheet`) via OPFS/IndexedDB in `vault.svelte.ts`; Stat Sheet templates stored in campaign IndexedDB/OPFS registry  
**Testing**: Vitest (`bun --cwd apps/web test`)  
**Target Platform**: Browser (Desktop & Mobile)  
**Project Type**: SvelteKit Web Application (`apps/web`) + Shared Schema (`packages/schema`)  
**Performance Goals**: `< 50ms` UI update latency for counter adjustments and 1-tap dice rolls  
**Constraints**: System agnostic (no automated rules/formulas), 100% client-side local-first privacy

## Constitution Check

_GATE: Must pass before Phase 0 research. Re-check after Phase 1 design._

1. **I. Library-First**: Schema types (`StatSheet`, `StatSheetField`, `StatSheetTemplate`) defined in `packages/schema/src/stats.ts`.
2. **II. Test-Driven Development (TDD)**: All store mutations, frontmatter serialization, template operations, and component interactions will have corresponding unit tests.
3. **III. Simplicity & YAGNI**: No automated rules engine or formula evaluators. Reuses existing `diceRollerService` for `Dice` field rolls.
4. **V. Privacy & Client-Side**: All stat sheet state and templates persist strictly in browser OPFS / IndexedDB.
5. **VI. Clean Implementation**: Svelte 5 Runes (`$state`, `$derived`), Tailwind 4 semantic tokens, Iconify utility icons (`icon-[lucide--...]`).
6. **VIII. Dependency Injection**: `StatSheetTemplateStore` uses constructor-based DI with singleton export.
