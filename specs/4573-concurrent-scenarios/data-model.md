# Data and limits

- **Session v3**: existing Adventure document plus optional `scenarioCollection`; omit singular `scenarioState` after migration. Both fields together are invalid, even if apparently equal. Keep existing world time, legacy GM threads and history references unchanged.
- **Collection v1**: `items` (0–8) and nullable `focusedScenarioId`. Focus must reference a heard, open item. Empty collection is valid; no scenario is required for ordinary play.
- **Item**: stable ID; immutable original seed and origin identity; `knowledge: unheard | heard`; `status: open | resolved | abandoned`; events (0–100); canonical/provisional anchor references (0–12 per item); secret bindings. Revealing the lead changes knowledge only, not hidden truth or quest acceptance. Ignored means heard/open with no focus. Resolved/abandoned are terminal in this slice.
- **Origin identity**: generated batch ID + selected index (1–6), or an existing saved source ID + immutable snapshot fingerprint + index, or legacy session ID + scenario ID, or an explicit manual creation ID. Compare structured tuples, not concatenated titles. Store each field within existing ID/text limits; never expose identity/fingerprint in player URLs/logs.
- **Secret bindings**: opaque IDs for baseline, investigation notes and GM event secrets. Allocate new IDs with injected UUID production defaults. For migration, reuse old registered IDs; when missing, deterministically choose the first free bounded legacy ID from a reserved prefix/counter, checking all existing IDs. Do not alias independent new scenarios by equal text. Preserve old revealed IDs referenced by turns.
- **Events**: retain existing validated fields and visibility. Event IDs are unique across scenarios; shared entity references may repeat intentionally. Identical event replay is already-applied; reused ID with different payload is a conflict. No event is discarded merely to make space.
- **Atomicity**: reducers return a candidate or typed failure, never partially mutate input. One existing repository save applies the candidate at its expected revision. Exact duplicate import/command does not increment revision or reapply focus; stale writes and origin/truth conflicts fail safely.
- **Budgets**: 8 items, 100 events/item, 600 normal text characters, 160 ID characters, existing 60-secret/40-thread limits and 32,000 aggregate state characters all apply together. Scenario anchors are context references, not automatically required session.sourceRecords; the grounding resolver selects relevant references within its existing 24-source cap. Explicit character/location choices retain their existing required-source semantics. Do not persist an expanded biography or another editable shadow scenario in GM threads. Prompt remains subject to existing 96,000 generation input budget.

Migration fixtures must include v1 ordinary, v2 ordinary, v2 single scenario with revealed baseline/event secrets, legacy world-entry/time-thread references, invalid mixed state, maximum IDs, future versions and repeated parsing. Migrating never writes until a normal explicit mutation/save succeeds.

A valid legacy record at the old state ceiling must not become unrecoverable merely because migration adds metadata. If the upgraded state cannot fit, return a typed migration-budget outcome with validated legacy read-only projection/export, preserve its bytes, and require capacity resolution before a v3 write. Do not auto-save the projection or drop events to hide the limit.
