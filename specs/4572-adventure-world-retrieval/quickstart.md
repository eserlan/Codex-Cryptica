# Validation guide

From repo root, install dependencies with `bun install --frozen-lockfile` if needed. Implement tests using existing Vitest and Adventure fixtures, with stubbed providers; no live model or private Vault required.

1. Use a canonical village/NPC, secret motive, future succession, provisional discovery and pending roll. Assert provider inputs for every inventoried path contain relevant sources and correctly classified knowledge.
2. Test direct and worker transports, successful empty search, failed/aborted lookup, stale session, missing required anchor and original roll/action reuse. Failed resolution must invoke no provider and write no session.
3. Run a deterministic 30-turn revisit/reload fixture and a 10,000-record retrieval-budget fixture. Record counts, source characters, body reads and lookup latency; never log private excerpts.
4. Run impacted checks: `bun run lint:changed`, `bun run test:changed` (these include local tracked changes; use --base origin/staging after committing); run web-scoped `bunx svelte-check --tsconfig ./tsconfig.json --threshold error` inside apps/web and the affected engine typechecks reported by `bun scripts/affected-workspaces.mjs --base origin/staging`.
5. Before commit/push run `bunx fallow audit --format json --quiet --explain --gate-marker agent`; before PR complete codex-review and all repository quality gates.

Manual smoke: start in an existing town, converse, resolve a roll, leave/return and resume after reload. Oracle uses established facts, reveals no hidden/future facts, and offers recoverable retry after a failed lookup. AI-disabled/read-only inspection remains usable.

## Recorded implementation validation (2026-11-03)

- Shared preparation covers opening, action, dice resolution and background rumours. Direct/worker payload parity, empty/error/cancelled/stale lookup, missing sources, and original roll/action reuse have deterministic coverage.
- The 10,000-record fixture hydrated 14 unique bodies in 28 reads, returned 14 sources (3,347 serialized source characters), and completed lookup in 22–33 ms in two local runs. These are synthetic local observations, not a production latency guarantee; model calls are excluded.
- The 30-action manager fixture includes failed lookup/retry, one roll outcome, revisit, persisted provisional discovery and reload; it commits 31 turns including opening. The existing engine 30-turn fixture also reloads a pending supplied roll and revisits the mill.
- Source tests cover temporal reclassification without loading newly ranked records beyond the initial bound, hidden/future GM-only projection, current-location graph retrieval and explicitly uncertain relationship provenance.
- The web worker build completed and its compiled-runes check passed. Static marketing files regenerated by the build were restored; no image assets were added.
- The new grounding service reached 94.91% statements and 83.78% branches in its final focused coverage run. Final lint, test, type and Fallow results are recorded in implementation-review.md after validation.

No live-model qualitative evaluation or remote staging walkthrough was performed. Deterministic provider stubs validate source delivery, projections and commit safety; model disclosure/continuity quality remains a separate evaluation concern. No atomic Vault snapshot is claimed.
